# P1 — สคริปต์สาธิตและทบทวนกับลูกค้า

ก่อนเริ่มเปิดหน้าแรก กด “รีเซ็ตข้อมูลตัวอย่าง” และชี้แถบ **ต้นแบบ — ข้อมูลสมมติ ไม่ใช่การลงคะแนนจริง** ทุกข้อมูลเป็นสมมติ ห้ามใส่ข้อมูลสมาชิกจริงในต้นแบบนี้

## 1. สมาชิกและการลงคะแนน

1. เปิด `#/user/login` ใช้ `000123`, ขอรหัสจำลองและกรอก `123456` → มี 1 รายการ
2. กดลงคะแนน ตรวจชื่อหน่วย เวลากติกา รูป/หมายเลขของผู้สมัคร ดูประวัติ/นโยบาย
3. แตะผู้สมัคร → ป๊อปอัปยืนยัน → กลับไปเลือกใหม่ หรือยืนยัน → กลับรายการ พร้อม “ใช้สิทธิ์แล้ว” และ “บันทึกคะแนนเรียบร้อยแล้ว” ไม่มีชื่อผู้สมัครในข้อความสำเร็จ
4. รีเซ็ตแล้วใช้ `000124` → มี 2 การเลือกตั้ง เปิดพร้อมกัน เลือกได้ 2 คนในใบผู้แทนพนักงาน ทดลองเลือกไม่ครบ/ครบ และตรวจ modal รายชื่อทั้งสองคน
5. รีเซ็ตใช้ `000123` → เลือก “ไม่ประสงค์ลงคะแนน” → ยืนยัน ใช้สิทธิ์แล้วเช่นกัน
6. เลือกเครือข่าย “ขาดหลังบันทึก” หรือ “ขาดก่อนบันทึก” → ส่ง → เห็น “ยังไม่ทราบผล” → ตรวจสถานะหรือส่งใหม่ด้วยคำขอเดิม ไม่ใช่บัตรใหม่
7. เปิดสองแท็บ Login บัญชีเดียวกัน เลือกต่างกันพร้อมยืนยัน ตรวจว่าต้นแบบบันทึกได้ครั้งเดียว
8. ใช้ `000126` เปิดลิงก์หน่วยจากผู้ดูแล → เห็นไม่มีสิทธิ์ ไม่มีชื่อ/รูปผู้สมัครใน DOM
9. ใช้บัญชี `000904` (ยังไม่เปิด), `000905` (ปิด), `000902` (ยกเลิก), `000906` (ประกาศปีเก่า) และลิงก์ผิด ดูข้อความสถานะ; ฉบับร่างตอบเหมือนลิงก์ไม่มีจริง
10. เปิดลิงก์หน่วยก่อน login แล้วเข้าสู่ระบบด้วยสมาชิกที่มีสิทธิ์ ตรวจว่ากลับหน่วยเดิม

คำถามลูกค้า SPEC §9 ข้อ 1–8: ความหมายหน่วย, หลายหน่วย/หนึ่งการเลือกตั้ง, ระดับจำนวนที่นั่ง/จำนวนเลือก, วิธีตัดสินเสมอ/turnout/ผู้สมัครคนเดียว, เวลาหน่วย, หลายตำแหน่ง, สิ่งที่สมาชิกเห็นหลังประกาศ, คะแนนเมื่อยกเลิกหน่วย
ให้ตรวจข้อความยืนยันหลายคนด้วย (OPEN-QUESTION §4.10)

## 2. ผู้ดูแลและข้อมูล

1. เปิด `#/admin/login` เลือกผู้ดูแลสูงสุด รหัส `demo123` ตรวจภาพรวมและตัวกรองการเลือกตั้ง/หน่วย/สถานะ/ค้นหา
2. สร้างการเลือกตั้งฉบับร่าง กำหนดเวลาไทยและกติกา ลองเวลาปิดก่อนเวลาเปิด และ min/max เกิน seats ต้องบันทึกไม่ได้
3. แก้ฉบับร่าง → เพิ่มหน่วย → ดูรายละเอียด → เพิ่มผู้สมัคร ลองหมายเลขซ้ำในหน่วยเดียวกัน (ห้าม) กับต่างหน่วย (ได้)
4. ตรวจ publicId สุ่มและลิงก์เฉพาะหน่วย คัดลอกและดาวน์โหลด QR PNG; เปิด preview พร้อมลายน้ำ ยืนยันแล้วคะแนนและสิทธิ์ไม่เปลี่ยน
5. เพิ่มผู้มีสิทธิ์ทีละคน แล้วนำเข้า Excel 8 ขั้น: แม่แบบ → เลือกไฟล์ → preview → ตรวจข้อมูล → จัดการแถว → ยืนยัน → บันทึก → สรุปผล
6. ไฟล์ควรมีรหัส `000128`, รหัสซ้ำ, รหัส `000125` ที่ใช้แล้ว, แถวว่าง, เซลล์ตัวเลข, สมาชิกเดิมต่างชื่อ/สังกัด/ติดต่อ ตรวจผลรายแถวและการเลือกใช้ทะเบียนเดิม/อัปเดตชื่อสังกัด; ช่องทางไม่อัปเดตอัตโนมัติ
7. นำเข้าไฟล์เดิมอีกครั้ง ตรวจว่าข้ามสิทธิ์เดิม ไม่รีเซ็ต has_voted และส่งออกรายงานได้
8. ลองเพิ่มสมาชิกหน่วยอื่นในการเลือกตั้งเดียวกันตามค่าเริ่มต้น: ถูกปฏิเสธ; ค่า multi-unit เปิดได้ในกติกาที่ไม่ล็อก
9. เปิดการเลือกตั้งที่กำลังเปิด ตรวจกติกา/เวลาเปิด/ผู้สมัครถูกล็อก ผู้ดูแลสูงสุดแก้คำผิดในประวัติได้พร้อมเหตุผล ขยายเวลาปิดต้องมีเหตุผล
10. Checklist เผยแพร่ต้องมีหน่วย ผู้สมัคร และผู้มีสิทธิ์ทุกหน่วยที่ใช้งาน

คำถามลูกค้า §9 ข้อ 1–6, 8, 14: ระดับกติกา, เวลาหน่วย, เงื่อนไขแก้ระหว่างเปิด, การยกเลิก, แหล่งข้อมูล/สิทธิ์แก้ช่องทางติดต่อ โดยเฉพาะความต่าง SPEC §2 กับ schema §6.3

## 3. คะแนน ผล และประวัติ

1. เข้าเป็น `live_results_viewer` ตรวจว่าดูคะแนนได้แต่ไม่มีเมนูรายชื่อรายบุคคล
2. เลือกหน่วยเล็ก 4 คน เห็นเฉพาะจำนวนผู้ใช้สิทธิ์ ไม่มีคะแนนรายผู้สมัครระหว่างเปิดหีบ
3. หน่วยใหญ่ดูคะแนน snapshot (ค่าจำลอง 10 นาที, k=5, ผู้ใช้สิทธิ์ขั้นต่ำ 10), polling 30 วินาที แสดงเวลาอัปเดต/การเชื่อมต่อและจำลองขาดการเชื่อมต่อได้
4. เข้า `results_certifier` เลือกหน่วยกรรมการตรวจสอบที่ปิดแล้ว มีคะแนนเสมอ → ต้องตัดสิน เลือกผู้ชนะและระบุเหตุผลก่อนรับรอง; ไม่มีประกาศอัตโนมัติ
5. เลือกหน่วยไม่มีผู้ลงคะแนน → ต้องตัดสิน; ตรวจจำนวนบัตรเทียบผู้ใช้สิทธิ์ก่อนรับรอง
6. หลังประกาศมี snapshot ผลและผู้รับรอง/เวลา ไม่รับรองซ้ำ และหน้าประวัติกรองปี/การเลือกตั้ง/หน่วยได้ ปี 2568 กับ 2569 ชื่อหน่วยเดียวกันแต่ข้อมูลคนละชุด

คำถามลูกค้า §9 ข้อ 4, 7, 9–11: กฎกรณีพิเศษ, ผลสมาชิก, ค่าคะแนนสด/บทบาทซ้อน/หน่วยเล็ก, ระดับความลับและผู้ดูแลโครงสร้างพื้นฐาน, เก็บบัตรรายใบหรือยอดรวม
อธิบายว่าต้นแบบไม่พิสูจน์ความลับจริง และระบบตาม SPEC ไม่ป้องกันผู้ดูแลโฮสต์/DB ได้เต็มที่

## 4. ตัวตนและการนำไปใช้จริง

1. หน้า login สมาชิกสลับตัวทดสอบรหัสหมดอายุ/ถูกล็อก ลองรหัสผิด; รหัสจำลองไม่ได้ถูกส่งจริง
2. เข้า helpdesk ใช้ `000127` จำลองตรวจบัตรก่อนออกรหัสสำรอง แสดงครั้งเดียว → ในแท็บเดียวกันเปิดหน้าสมาชิกใช้รหัสนั้น ไม่ต้องขอ OTP
3. สรุปช่องทางจริงและโครงสร้างพื้นฐานก่อนเข้าสู่ P2 โดยบันทึกคำตอบใน decisions.md แล้วปรับ SPEC

คำถามลูกค้า §9 ข้อ 12–19: SSO, ช่องทางส่งรหัส/คนไม่มีติดต่อ, แหล่งข้อมูล/สิทธิ์แก้, helpdesk/ร้องเรียน, hosting/นโยบายองค์กร, สมาชิกและโหลดพีค, งบและวันใช้งานจริง, retention/log/ลบข้อมูล

## บันทึกผล review

บันทึกผู้ทบทวน วันที่ หน้าจอที่ผ่าน/ต้องแก้ และคำตอบ §9 พร้อมข้อจำกัดแยกจากสมมติฐาน การผ่าน test ของทีมไม่ใช่การเซ็นรับ P1 ของลูกค้า และไม่ใช่การอนุญาตใช้คะแนนจริง
